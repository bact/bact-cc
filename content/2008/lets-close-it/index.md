Let’s close [Firefox Thai bug reports](https://bugzilla.mozilla.org/show_bug.cgi?id=thai "[Bug 65896] Thai support -- tracker bug")

บรรยากาศ ปิดงาน[บั๊กภาษาไทยในไฟร์ฟอกซ์](https://bugzilla.mozilla.org/show_bug.cgi?id=thai "[Bug 65896] Thai support -- tracker bug") ตอนนี้คึกคัก (เช่นคุณ [kengggg](http://keng.ws/) ที่วันนี้กระหน่ำ add cc บั๊กต่าง ๆ :P)

ซึ่งหลาย ๆ คนก็ได้พยายามประชาสัมพันธ์เรื่องนี้ ให้มาช่วยทดสอบกันหน่อย เพราะที่ผ่านมา มีการแก้ไขไปแล้วหลายส่วน แต่ยังไม่มีการทดสอบกันเท่าไหร่นัก ทำให้บางบั๊กยังปิดไม่ได้ (เพราะไม่แน่ใจว่าแก้ได้จริงรึยัง หรือแก้อันนี้แล้วไปทำให้เกิดบั๊กที่อื่นรึเปล่า ฯลฯ) ซึ่งก็มีทั้งการส่งเมลหากัน หรือบอกกล่าวกันในบล็อก เช่นที[มาร์คโพสต์ไป 3 ที่](http://isriya.com/node/1775 "Problem of Open Source in Thailand") (ความเห็นของมาร์คและหลาย ๆ คนในโพสต์นั้น น่าสนใจ ลองไปอ่านกันดู จะเห็นทัศนคติที่หลากหลาย)

ข้อสังเกตหนึ่งที่ผมเห็น จากการติดตามดูความเคลื่อนไหวใน bugzilla ก็คืองาน contribution จากผู้ใช้ ลีนุกซ์ กับ แมคโอเอส มีมากกว่าจาก วินโดวส์ ?? ไม่รู้ว่าคิดไปเองรึเปล่า  
นี่ไม่พูดถึงเรื่องโค้ดนะครับ (ซึ่งหลัก ๆ จริง ๆ เนี่ย ถ้าไม่นับที่ทีมซันเคยทำไว้เมื่อ 2002 กับที่พี่สัมพันธ์เคยทำไว้เมื่อก่อน ตอนนี้หลัก ๆ เป็น[พี่เทพ](http://thep.blogspot.com/)ล้วน ๆ เลย) นับแค่เรื่องทดสอบว่า ตกลงมันใช้ได้รึยัง หรือจับภาพหน้าจอ screenshot มาแปะให้ดูกัน ดูทางวินโดวส์จะมีน้อยกว่า (ทั้ง ๆ ที่ผู้ใช้วินโดวส์น่าจะมีเยอะกว่าระบบปฏิบัติการอื่น) — แต่ก็อาจจะเป็นเพราะ คนใช้วินโดวส์ส่วนใหญ่ก็ใช้ไออี และถึงแม้จะใช้ไฟร์ฟอกซ์ ไฟร์ฟอกซ์บนวินโดวส์มันก็มีปัญหาน้อยกว่าด้วยแหละ เป็นไปได้

ตอนนี้มีหลายบั๊ก/การแก้ไข ที่รอการยืนยันจากผู้ใช้ในแพลตฟอร์มต่าง ๆ ยังไงถ้ามีเวลา ก็ไปช่วยดู ๆ กันนะครับ ที่:

**[\[Bug 65896\] Thai support — tracker bug](https://bugzilla.mozilla.org/show_bug.cgi?id=thai)**

กดไล่ไปดูทีละอันเลยครับ (จะมีรายการลิงก์) อันไหนที่~~ถูกขีดฆ่า~~ แปลว่าบั๊กนั้นปิดไปแล้ว (ถูกแก้ไขแล้ว รายงานผิดพลาด ซ้ำ ฯลฯ) ก็ข้ามไปเลย  
บางบั๊กก็จะเป็นกับทุกระบบปฏิบัติการ บางอันก็จะเป็นเฉพาะกับวินโดวส์ กับแมคโอเอส อะไรแบบนี้ ก็เลือกทดสอบกันครับ

หลายอันเป็นเรื่องง่ายมาก ๆ เช่นให้ลองดูว่า ข้อความนี้บนหน้าจอไฟร์ฟอกซ์ของคุณ แสดงผลถูกต้องไหม  
หรือ ถ้าคุณลองกดปุ่ม delete ข้อความที่กำหนด แล้วผลลัพธ์เป็นยังไง  
ใครใช้เว็บเบราเซอร์เป็น ก็ช่วยทดสอบได้ทุกคนครับ ไม่มีอะไรยากเลย

หลังจากทดสอบแล้ว จะออกความเห็น หรือส่งรูปจับภาพหน้าจอ<sup>\*</sup> ก็สามารถทำได้สะดวก เพียงสมัครสมาชิกกับ [Bugzilla](https://bugzilla.mozilla.org/) ก่อน (แป๊ปเดียว) แล้วก็โพสต์ได้เหมือนกับเว็บบอร์ดเลย

<sup>\*</sup> บนวินโดวส์/ลีนุกซ์ การจับภาพหน้าจอ ทำได้ง่าย ๆ แค่กดปุ่ม Print Screen / PrtSc บนคีย์บอร์ด รูปหน้าจอของเราก็จะไปอยู่ในคลิปบอร์ด แล้วเราก็เปิดโปรแกรมวาดรูปดูรูปอะไรก็ได้ แล้ว paste มันลงไปเป็นไฟล์ใหม่ แค่นี้ก็จะได้ภาพหน้าจอแล้ว

และบางครั้ง เราก็จะพบว่า การช่วยกันทดสอบซอฟต์แวร์ตัวหนึ่ง อาจนำไปสู่การพบบั๊กหรือการเปลี่ยนแปลงในซอฟต์แวร์ตัวอื่นด้วยก็เป็นได้ เช่นในกรณีบั๊ก [การลบตัวอักษร พินทุ ใน GNOME](http://bugzilla.gnome.org/show_bug.cgi?id=518084 "Thai is not Virama language") ที่พบระหว่างการทดสอบบั๊ก [ปุ่ม \<delete\> ใน Firefox](https://bugzilla.mozilla.org/show_bug.cgi?id=157546 "<delete> key should delete WHOLE Thai 'display cell'")  
หรือคำถามถึงฟอนต์ Thonburi ในแมคโอเอส ที่ถูกถามอีกครั้งในบั๊ก [ฟอนต์ตั้งต้นในแต่ละแพลตฟอร์ม](https://bugzilla.mozilla.org/show_bug.cgi?id=284265 "Default Thai fonts should be set appropriately on each platform")

ทุกสิ่งล้วนเกี่ยวข้อง ผลักอันนี้ อันอื่นก็เขยื้อนด้วย
